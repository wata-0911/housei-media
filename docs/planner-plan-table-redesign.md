# 履修計画表の再設計

## 最終情報設計

Plannerは「履修計画」と「メディア進捗」の二つの表示に整理した。履修計画は、所属設定、全科目の計画・進捗・最終評価、卒業要件を一画面に並べる。通信学習と評価・成績の独立タブは廃止し、通信の詳細は該当行を展開して編集する。メディアだけは回別の動画・テストとSNS共有の情報量が大きいため、専用タブを維持する。

## 年度・学年・時期

- `plannedYear` は従来どおり4桁の計画年度（例: `2026`）であり、意味を変更しない。
- `studyYear` は履修学年（`1`〜`4` または `null`）で、年度とは独立している。
- `plannedTerm` は履修時期として `前期 / 後期 / 通年 / 夏期 / 冬期 / その他` を標準候補にする。

既存の `plannedTerm` は移行で書き換えない。標準外の既存文字列は表で「保存済み（要確認）」と表示して選択肢にも残す。春休みのリポート作成や4月の試験のような個別の行動予定は履修時期ではなくTodoの責務である。

## 履修形態と進捗

履修形態は手入力しない。`method === correspondence` は通信、既存の構造化メディア判定はメディア、残りの `schooling` はスクーリングと表示する。科目名の部分一致では判定しない。

進捗表示は純関数でstateから生成する。通信は合格済みリポート数と試験評価を表示し、必要リポート数が未確認なら分母を作らず「リポート要件 未確認」とする。メディアも総回数が未設定の場合は分母を表示しない。スクーリングは既存の履修状態を安全な要約として使う。

## 評価の役割

v8で `CourseEvaluation.finalGrade` を追加した。これは科目としての最終評価であり、直接入力する。入力しても `PlannerItem.status` や卒業要件の修得判定は変更しない。

- `correspondenceProgress.reports[]`: 通信の設題別リポート状態・評価
- `correspondenceProgress.examGrade`: 単位修得試験評価
- `courseEvaluations.finalGrade`: 科目の最終評価
- `courseEvaluations.reportGrade` / `schoolingGrade`: 既存のmethod別・legacy記録として保持

v7からv8への移行では、既存データを保持し、`studyYear` と `finalGrade` はすべて `null` で追加する。legacy評価から最終評価を自動算出・移行しない。localStorage keyは引き続き `hosei-planner:v1`。

## 表・公開科目・削除

PCでは列形式、390px相当では横スクロールしない縦型カードを使う。科目は `1年 / 2年 / 3年 / 4年 / 未設定` でグループ化する。公開科目も同じ表に入り、名称、年度、学年、時期、状態、最終評価を編集できる。既存のlatest-only Undoと、削除後の通信・メディア・評価のorphan保持は変更しない。

卒業要件は計画表の直下へ置く。計算は既存ロジックのままで、修得扱いは `status === earned` のみである。`graduationCheckComplete=false` も維持する。

## 未実装

認証、プロフィール、CSV出力、画像exportは本featureの対象外。プロフィールは将来的に、計画表・通信進捗・メディア進捗を集約する認証後の閲覧中心画面として実装する。
