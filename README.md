# 法政通信メディア

法政大学通信教育部の学生向けに、履修・単位修得・試験・スクーリング・学生生活などの情報を提供するWebサービスです。

学生有志によって運営されており、React / TypeScriptを中心に開発しています。

**本サイトは学生有志による非公式サイトであり、法政大学の公式サイトではありません。**

## 公開サイト

**https://hosei-tsukyo-media.com/**

本番サイトは`main`ブランチから公開しています。

履修プランナーは現在`dev`ブランチで開発中であり、**本番サイトではまだ公開していません。**

## 主な機能

### 公開中の機能

- **Q&A検索**：キーワード検索、カテゴリ別表示、URLクエリとの同期
- **X投稿表示**：Google Apps Scriptを介して最新投稿を取得・表示
- **お問い合わせ**：GAS経由で送信し、通信エラーやタイムアウトにも対応
- **大学行事カレンダー**：年間スケジュールを画像で掲載
- **運営メンバー紹介**：運営者のプロフィール表示
- **創立者メッセージ**：サイト設立の背景を掲載

### 開発中：履修プランナー

法政大学通信教育部の学生が、履修科目・修得単位・学習進捗を管理し、履修計画を立てるためのWebアプリケーションです。

主な機能・開発対象：

- 履修科目の検索・登録と年度別の履修計画
- 履修状態・学習進捗・修得単位の管理
- 成績情報の取り込みと確認
- 学科別の卒業要件の部分進捗表示
- データのバックアップ・復元
- 不正な保存データの検出と保護
- 年度ごとの開講情報に依存しない履修データモデルへの移行

卒業要件の計算では、公式成績と手動入力の二重計上防止、未確認情報の判定保留、データの整合性を重視しています。

**大学による正式な卒業可否判定を行うものではありません。**

現在も機能開発と検証を進めており、一部の機能は開発・テスト環境に限定されています。

## 開発で取り組んだこと

### 1. JavaScriptからTypeScriptへの移行

既存のReactアプリケーションをJavaScriptからTypeScriptへ移行し、型安全性や保守性の向上に取り組みました。

### 2. 履修プランナーの企画・設計

通信教育課程の履修計画や単位管理の複雑さを踏まえ、履修プランナーを企画しました。

科目データ、複数の履修方法、学科別の卒業要件などを整理し、段階的な開発計画と仕様を設計しています。

### 3. データの安全性と整合性

ブラウザに保存したデータの破損、複数タブ間の競合、バックアップからの復元などを考慮した設計に取り組んでいます。

特に卒業要件の計算では、公式修得単位と本人入力を区別し、不明な情報を根拠なく確定扱いしないことを重視しています。

### 4. AIを活用した開発・検証

AIコーディング支援を活用して、機能の実装、テスト作成、コード調査を進めています。

自身は主に、機能の企画、要件定義、設計方針の検討、AIへの実装指示、Pull Requestの監査、受け入れ基準の確認、最終的なマージ判断を担当しています。

AIによる実装結果についても、仕様との整合性や回帰テストの結果を確認しながら開発しています。

## ローカル開発

Node.js 22系とnpmを使用します。

```bash
git clone https://github.com/wata-0911/housei-media.git
cd housei-media
npm ci
npm run dev
```

上記はリポジトリのデフォルトブランチを取得します。開発中の履修プランナーを確認する場合は`dev`ブランチを使用してください。

## 品質チェック

```bash
npm run typecheck
npm run lint
npm run test:planner
npm run test:extension
npm run test:bookmarklet
npm run build
```

これらのテスト用スクリプトは主に`dev`ブランチにあります。

GitHub Actionsでは、`main`へのpush、および`main`・`dev`向けのPull Requestで、型検査・Lint・自動テスト・ビルドを実行しています。

ブラウザを操作するテストも用意していますが、すべてのブラウザテストがCIで実行されるわけではありません。

## ブランチ構成

| ブランチ | 用途 |
|---|---|
| `main` | 本番公開用 |
| `dev` | 開発・統合用 |
| `feature/*`・`fix/*`・`docs/*`など | 機能開発・修正・ドキュメント整備 |

変更は原則として作業ブランチで行い、Pull Requestを経由して`dev`へ統合します。

本番への反映は検証後、`main`へ統合して行います。
